## Design Context

### Users
Power developers and automation enthusiasts who demand speed and precision. They summon Script Kit and say what should happen — typed or spoken — and it must appear instantly, understand them without lag, and get out of the way the moment the task is done. The interface should evoke **confidence**: every interaction feels deliberate, fast, and under their control.

### Brand Personality
**Fast. Focused. Minimal.**

Script Kit is a sharp tool, not a playground. It respects the user's time and attention. No unnecessary animation, no visual noise, no chrome that doesn't earn its place. The gold accent (#fbbf24) is the one warm touch — a signature that says "this is Script Kit" without shouting.

### Aesthetic Direction
- **Reference:** Raycast for density and keyboard-first flow; Apple's Tahoe Liquid Glass for material, the floating capsule, and fast fades.
- **Anti-references:** Electron apps with visible latency, over-decorated dashboards, anything that feels like a web page pretending to be native. Hover-dependent UIs that hide functionality behind mouse discovery. Popups, toasts, and dialogs that pull the eye away from where the user is typing.
- **Theme:** Dark mode primary with native macOS glass. Semi-transparent backgrounds let the desktop bleed through. Light mode supported but secondary.
- **Visual tone:** Native macOS feel — if Apple made a scriptable launcher that understood sentences, it would look like this. Precision over personality.

### Design Principles

1. **One window, one input** — The main window is the only window. Everything — lists, forms, answers, notes, the model's chat, agents, voice, SDK prompts — opens in place under the same input. Nothing floats over it: no popups, toasts, HUDs, or modal dialogs.

2. **The input never moves** — The input is the anchor for the user's eye. The launcher puts subject tabs below the input; other list views keep the status line above it. The window keeps one height while visible. Typing and later results never resize it.

3. **Say what should happen** — Local search accepts names and commands. With remote readings enabled, Jev offers interpretations of a sentence; symbols (`@`, `/`, `.`, `>:`, `|`, `;`, `due:`) say it exactly. The words stay white; colored underlines show which part is the subject, action, target, details, and owner.

4. **Three keys, nothing more** — The capsule shows at most three affordances: ↵ (named for exactly what Enter runs), ⌘K (act on the focused thing), and ⌘↵ ("Agent" on an empty input, "Do It" — Jev's first reading — once words are typed). ↵'s label never flips back while a sentence is typed forward. Anything else belongs behind ⌘K, not in the chrome.

5. **Act in place** — ⌘K stages the focused thing in the line above the input and the list becomes what you can do with it. Esc lets go and the view returns exactly as it was.

6. **Declare risk, don't ask** — Irreversible actions wait 8 seconds in the line and run unless stopped; reversible actions happen at once with ⌘Z. A question that truly needs an answer is staged in the line, with its answers as rows.

7. **Peek, don't clutter** — For list-only surfaces, detail lives behind ⌘I (info/peek). Press to see, Esc to return. No inline expansion, no hover cards, no progressive disclosure on mouse. Exception: when the preview IS the experience (clipboard content, file preview, live theme swatch), a split panel is justified — see Surface Layouts below.

8. **Whisper chrome** — UI surfaces use ultra-low opacity (0.03–0.06 at rest). Borders are hairline or absent. Backgrounds are barely perceptible. Content gets full opacity; everything else fades to near-invisible. Let glass and spacing define structure, not boxes and dividers.

9. **Speed is the design** — Every pixel serves instant comprehension. If an element slows the user down (visually or mechanically), remove it. Sub-frame response to input is non-negotiable. The window fades in and out fast and never grows or shrinks to appear.

10. **Keyboard-first, always** — The mouse is a fallback. Every interaction must be reachable and obvious via keyboard. Visual affordances reinforce keyboard shortcuts, not compete with them.

### Text Opacity Tiers (theme-configurable)

All text elements use `text_primary` (white on dark, black on light) as the base color. Brightness is controlled purely via these semantic opacity tiers — no double-dimming from secondary/muted/dimmed base colors. These live on `BackgroundOpacity` and are configurable per-theme.

| Tier | Default | Theme field | Use |
|------|---------|-------------|-----|
| **Name** | 1.0 | `text_name` | Names, primary labels — always full brightness |
| **Strong** | 0.80 | `text_strong` | Badges, shortcuts, section headers — clearly readable chrome |
| **Muted** | 0.65 | `text_muted_alpha` | Focused descriptions, source hints — readable but secondary |
| **Hint** | 0.45 | `text_hint` | Hovered descriptions, type labels — visible but recessive |
| **Placeholder** | 0.40 | `text_placeholder` | Placeholders, idle captions, header hints |
| **Icon** | 0.50 | `text_icon` | Idle icons — recedes behind name text |

### Background Opacity Tiers

| Tier | Range | Use |
|------|-------|-----|
| **Ghost** | 0.03–0.06 | Row hover bg, whisper surfaces, dividers |
| **Subtle** | 0.15–0.20 | Subtle highlights |
| **Medium** | 0.40–0.55 | Input backgrounds, panels |
| **Solid** | 0.75–1.0 | Window surface, capsule |

### Interaction State Ladder

Hover, focus, and active/toggle states are always visually distinct — even over glass.

| State | Treatment | Purpose |
|-------|-----------|---------|
| **Idle** | Transparent row, icon at 50% | No background |
| **Hover** | `text.primary` at 0.06 (bg) | Ghost-tier row tint; text grading provides the real affordance |
| **Focused / Selected** | `text.primary` at 0x20 (12.5%) row fill; the 24 pt icon tile fills gold (#fbbf24 at 95%) | The fill carries focus even when an app icon's own colors hide the tile; description grades up to muted opacity |
| **Active / Toggle** | Same as Focused | Pressed/toggled buttons match focused style exactly |

**Raycast-style text grading:**

| Text element | Idle | Hovered | Focused | Tier |
|-------------|------|---------|---------|------|
| **Name** | 100% | 100% | 100% | `text_name` |
| **Description** | hidden | 45% | 65% | `text_hint` / `text_muted_alpha` |
| **Icon** | 50% | 50% | 100% | `text_icon` |
| **Source hint** | hidden | 45% | 45% | `text_hint` |
| **Section header** | 80% | — | — | `text_strong` |
| **Badge / shortcut** | 80% | 80% | 80% | `text_strong` |
| **Placeholder** | 40% | — | — | `text_placeholder` |

**Rules:**
- All text uses `text_primary` as the base color. Opacity alone controls brightness.
- Row bg stays transparent or ghost so the glass shows through; the icon tile and text grading carry the visual weight.
- Active/toggle states match focused style. Hovering over active keeps active style.
- Chrome tokens `hover_rgba` and `selection_rgba` resolve from `text.primary` in `src/theme/chrome.rs`; the tile color and row geometry live in `crates/sk-one-window/src/contract.rs`.

### Window Anatomy

The tabbed launcher starts with the input, then the 38 pt subject tabs and their action list. Status, Stop and Undo share the Today footer position. Outside that shell the order is:

1. **The line** (34 pt) — always present, one height. It says what's staged ("Acting on …"), what's waiting ("Runs in 8s"), what just ran ("Last · … just now"), or what "this" means ("Focused"). Its words swap in place; only its dimming eases.
2. **The input** — the anchor. It never moves. Text stays white; word marks are 2 pt underlines in the word's color.
3. **The list** — always led by a 28 pt section header. Rows are 44 pt. Jev's readings take three reserved rows under "Jev · ⌘1–3".
4. **The capsule** — floating Liquid Glass, bottom right, inside the glass stage. Only the list scrolls under it.

### List Item Anatomy

**Unfocused row:** 24 pt icon tile + name at full white. Right-aligned metadata in hint opacity. No description. No borders. No row dividers. No per-row keycaps.

**Hovered row:** Name stays full white. Description appears at 45% opacity (hint tier). Ghost-tier bg tint (0.06).

**Focused row:** A soft row fill (`text.primary` at 0x20) and the icon tile fills gold (#fbbf24). No selection bar, no title underline, no outline. Name full white. Description at 65% opacity (muted tier). Right-aligned metadata tags in muted opacity.

**Section headers:** Uppercase label at strong tier (80%). Count and icon at muted tier (65%). No separator lines — spacing alone defines groups. The first header never disappears while typing.

**Capsule:** `↵ <what Enter runs> · ⌘K Actions · ⌘↵ Agent` at most. Right-aligned. Nothing else.

### Surface Layouts

#### The Decision Rule

**Ask: "Is the list item the content, or a label pointing at content?"**

- If the name IS the thing (a script, an app, a process, an emoji) → **Mini view**. The list item is self-selecting. ⌘I shows configuration, metadata, settings — useful but not required to choose.
- If the name is a LABEL for content you can't see (a clipboard entry, a file, a theme, a window) → **Expanded view**. The list item is meaningless without its preview. You can't confidently select without seeing what it points to.

#### Mini View (list-only + ⌘I info)

Use when the list item name is sufficient to make the right selection. ⌘I info shows configuration and metadata — things you might want to know but don't need to choose.

| Surface | Why mini works | ⌘I info shows |
|---------|---------------|---------------|
| Main list | "Summarize" is self-explanatory | Description, shortcut, script path, last run |
| App launcher | "Slack" is obvious | App version, path, bundle ID |
| Process manager | Process name + PID is enough | Memory, uptime, CPU, logs |
| Favorites | Script name tells you what it does | Same as main list info |
| AI presets | Preset name describes behavior | Full system prompt, model, parameters |
| Emoji picker | Grid layout — visual content scanned by shape, not name | (see Grid layout below) |

#### Expanded View (list + preview split)

Use when the list item is a label pointing at content that must be seen to select correctly. The preview IS the decision — removing it would force blind selection.

| Surface | Why expanded is required | Preview shows |
|---------|------------------------|---------------|
| Clipboard history | "Text clip from 2m ago" could be anything | Full text/image content |
| File search | Filename alone can't distinguish similar files | File content, image thumbnail |
| Theme chooser | "Nordic Frost" is meaningless without colors | Live color preview, the theme applied |
| Window switcher | Multiple "Safari" windows need differentiation | Window thumbnail |

**Rules for the expanded split:**
- List side follows the main list anatomy (gold icon tile + name, no selection bars or row dividers)
- Preview side is chromeless — content flush, no wrapping borders or headers
- Divider between panels: hairline or spacing only
- The capsule still follows the three-key pattern
- No additional chrome around either panel

#### The Litmus Test

> If you deleted the preview panel and a user said "I can still pick the right one" → it's a mini view.
> If you deleted the preview panel and a user said "I'm guessing now" → it's an expanded view.

#### Other Layouts

**Views Jev assembles** (forms, answers, steps, connect): no form per intent. Fields appear in the order Jev read them, each says where its value came from, and the field Jev couldn't fill takes the caret. Same input, same line, same capsule.

**Editor** (code editor prompt): Justified exception — the editor surface needs its full area. The capsule stays.

**Grid** (emoji picker, icon browsers): Grids are the correct layout when content is inherently visual and high-density — emoji, icons, images. You don't scan emoji by name, you scan by shape. The grid stays. Apply the same shell around it (the one input, the line, the capsule) but keep the grid itself.

### Actions (⌘K)

⌘K is the single discovery surface, and it is not a separate UI: it stages the focused thing in the line above the input ("Acting on …"), and the list becomes that thing's actions under "Say what to do with it, or pick one". Typing filters them in the same input; Enter runs one; Esc lets go and the view returns exactly as it was.

**Row anatomy:** Same as every list — action name left, row fill and gold icon tile when focused, no row dividers. Destructive actions use red text and run through the 8-second hold rather than a confirmation.

**Section headers:** Uppercase category labels (Actions, Edit, Share, Destructive), same as every list's headers.

### Interaction Model

| Key | Action | Scope |
|-----|--------|-------|
| **Enter** | Run exactly what the ↵ label says | Universal |
| **⌘K** | Stage the focused thing and list its actions | Universal — the single discovery surface |
| **⌘↵** | Empty input: open the model's chat ("Agent"). Words typed: run Jev's first reading ("Do It") | Universal |
| **⌘1–3** | Run one of Jev's readings | Main list |
| **↑** (empty input) | Select the last run; press again to walk back through run history | Main list |
| **⌘Z** (empty input) | Undo the last reversible action, or stop a waiting hold | Universal |
| **Tab** | With words typed, hand them to an agent (Tab again takes them back); on an empty tabbed launcher, cycle subjects (Shift-Tab goes back) | Main list |
| **⌘J** | Open the agent that needs you | Universal |
| **⌘I** | Info / Peek | Universal — toggles detail view, Esc to return |
| **Esc** | Back one step | Universal — lets go of what's staged, then goes back one view with that step's words, then clears the input, and only then hides the window |
