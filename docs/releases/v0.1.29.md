# Script Kit 0.1.29 — a dependable Return action

If you pick a browser tab and then rearrange your tabs, Kit checks the browser, window and page again before switching. Window actions also refuse a stale target rather than moving a different document. “Focus on the release tab” uses the same checks as picking a tab from the list. Kit reports success only after it finds the requested page in the front window of the active browser. Safari does not expose a stable tab ID: Kit checks for a unique title and URL in the original window, but cannot distinguish an identical replacement there.

- **Return.** With remote readings off or unavailable, the launcher immediately names the selected local action. A background search no longer appears to change it. When a reading finishes between frames, the footer follows the new Return action without waiting for another keystroke. The launcher reports the same action to automation.
- **Notes.** Deleting a note while Kit rebuilds the search index no longer interrupts indexing for the remaining notes. If an agent pipes a note or handoff to `scriptkit` in the wrong encoding, the CLI refuses invalid UTF-8 before it sends any text.
- **Local connections.** By default, `scriptkit mcp` sends Kit’s saved credential only to the address recorded with it. To connect to a different local server, supply that server’s credential. If the CLI or an SDK computer helper reports invalid JSON in the connection file, restart Kit to recreate it; you don’t need to share the file to diagnose the error.
- **Settings.** The installed settings tools use your active workspace. The settings tools read and validate changes without running your config. If a native edit or backup restore needs a Bun compile-time macro, change the file manually; Kit will not run the macro to check your settings. Revision checks prevent stale edits from overwriting newer ones. When Kit changes a preference in a nonempty `config.ts`, it first saves the original as `config.ts.bak`. If it cannot read the settings, save the backup, or validate the change, it leaves the current config alone. Enabling Claude Code changes only `claudeCode.enabled` in the active workspace, not your CLI path, permissions, tools or additional folders. If Kit cannot tell which setting to change, edit that field yourself in `config.ts`. A rejected edit does not restore an older backup. If Kit detects a change to a pending save, it stops rather than installing the changed draft. Reread your settings and check for another writer before trying again; do not remove a lock another writer may still be using. Executable paths and sensitive switches remain manual edits.
- **Agent Chat.** If you narrow a profile’s tools or allowed folders, start a new chat to use the new permissions. Kit won’t hand it an older session with wider access. If your engine settings enable shell or file editing by default, Kit removes those extra tools from the new session and checks what remains before sending your message. Your engine settings and other chats are left alone. Close an existing chat when you no longer want it to use its original tools.
- **Command-line setup.** When Kit updates its workspace command, it makes the new copy executable before putting it in place. A failed update no longer grants access to a private directory or linked file at that path. `scriptkit install-command` checks where an existing link actually leads before reporting success. It won’t approve another executable just because the path looks right. Quoted target names keep their spaces, and asking for help does not install anything. `scriptkit install-skill` refuses a destination containing `..` instead of choosing a neighboring agent’s directory. Missing or invalid skill instructions no longer leave an empty installation behind. When you run `scriptkit` directly, it ignores the current project’s Bun preloads and `.env` files. Use shell exports for a custom workspace or connection.
- **File handoffs.** A quoted `@file:` path stays one attachment when you send a launcher prompt, even if the volume or file name contains spaces.
- **Pinned launcher.** While dictating, the pin stays beside the input. The recording line shows the destination and controls without repeating “Stays open.”
- **Scripts.** Kit checks for a directly installed Bun even when Finder has not loaded your shell configuration. If mise or asdf has several versions, set `bun_path` in `config.ts` to the full path of the executable you want. A symlink to that executable works; a link through a manager or package shim does not. See [Getting started](https://github.com/johnlindquist/script-kit-next/blob/v0.1.29/docs/guides/getting-started.md).
- **Upgrades.** Choosing an alternate workspace with `SK_PATH` skips automatic import from `~/.kenv`. Kit does not merge a legacy workspace into an existing `~/.scriptkit`. If the legacy layout contains unrecognized files, keep it intact and use **Migrate v1 Scripts** to review your scripts. You do not need to recreate your scripts or `config.ts` when installing an app update.
- **Permissions.** An unreadable permission isn’t a grant. Kit distinguishes permission to post a keystroke from the Accessibility access needed to identify the original field. If Kit cannot safely deliver dictated text there, review the text in Kit. A microphone grant alone does not prove a device is present or receiving sound.
- **Backups.** Sync to GitHub exports eligible personal files to the `script-kit-personal` branch of a verified private repository. It does not push your workspace’s Git history, notes, recordings, config, tokens or vault. Review the scripts you author: they can contain private information. Older remote history is not erased.
- **External agents.** If an explicitly selected agent credential is empty or invalid, the CLI stops rather than switching to operator access. Leave unused connection overrides unset. Keep each agent’s credential in a private folder outside your scripts. Kit refuses a file in a linked plugin’s script folder even when you supply its external path. It also refuses a file already linked as a launcher script. Moving a previously shared credential does not revoke it; follow the [grant and revocation guide](https://github.com/johnlindquist/script-kit-next/blob/v0.1.29/docs/guides/external-agents.md).
- **Saved credentials.** New vaults use a random identity stored in the macOS Keychain. A readable older vault is upgraded on access; a locked vault or missing key is not treated as an empty vault. Back up the Keychain securely as well as the encrypted file.

## For script authors

The settings SDK refuses to edit or reset a file when a line break separates the exported object from `as` or `satisfies`. Keep the annotation with the closing brace, like `} satisfies Config;`.

- An HTML display can return a string (including `""`), `null` on dismissal, or `undefined` if its reply omits the value. The SDK type now reflects those outcomes. Use `typeof result === "string"` when the empty choice matters.
- Window scripts now distinguish “no previous window” from “Kit couldn’t identify the window.” `getFrontmostWindow()` still returns `null` for no window; a failed lookup or invalid target rejects instead of letting a script act on a missing window ID.
- SDK window listing and capture use the credential you supply. With a notes-only credential, these helpers return a denial instead of using the operator connection. See [Computer use](https://github.com/johnlindquist/script-kit-next/blob/v0.1.29/docs/guides/computer-use.md) for connection options.
- The CLI keeps spaces in workspace and connection filenames. SDK and CLI workspace paths containing `..` are refused, so a link cannot redirect a settings edit, agent grant, or connection to a neighboring workspace. Use the full path of the intended directory.
- The settings SDK no longer turns a missing key into a request for all settings, or a missing revision into an unconditional save. Use `config.reset(key, revision)` for one setting and `config.resetAll(revision)` for an intentional whole-config reset.
- The settings SDK preserves Unicode folder names, including emoji. If a helper reply is unreadable after a save, read the setting and its revision before trying another edit.
- If a settings command returns `settings_write_displaced`, let the active writer finish and read the settings again before trying a new edit. Do not remove another writer’s lock.

## Download and check the Mac app

On [GitHub Releases](https://github.com/johnlindquist/script-kit-next/releases), look for **v0.1.29 → Assets → Script-Kit-macos.zip**. If the release or that asset is missing, there is no public Mac download for this version. GitHub’s automatic source archives and a ZIP from a different release are not substitutes.

To check the download before opening it, save **release-manifest.json** from the same release beside the ZIP. In Terminal, in that folder, run:

```sh
check_kit_zip() (
  zip=Script-Kit-macos.zip
  field() { /usr/bin/plutil -extract "$1" raw -expect "$2" -o - release-manifest.json; }
  tag=$(field tag string) && count=$(field artifacts array) &&
    name=$(field artifacts.0.name string) && digest=$(field artifacts.0.sha256 string) &&
    sum=$(/usr/bin/shasum -a 256 "$zip") &&
    [ "$tag" = "$1" ] && [ "$count" = 1 ] && [ "$name" = "$zip" ] &&
    [ "${sum%% *}" = "$digest" ] || {
      printf 'Missing file, wrong release, or checksum mismatch. Do not install.\n' >&2
      exit 1
    }
  printf '%s matches the %s manifest.\n' "$zip" "$tag"
)
check_kit_zip v0.1.29
```

This checks the version, archive name and downloaded bytes. It does not authenticate the publisher or replace macOS security checks.

Unzip the matching archive, move **Script Kit.app** to **Applications**, and open it there. The release checks target Apple Silicon on macOS 15; older systems have not been qualified. Install Bun to run scripts. Voice models download on demand.

You don’t need blanket permissions to try the launcher or a local note. If Kit opens **Set Up Permissions**, press Esc to return to the launcher. Grant access only for the feature you want. [Permissions](https://github.com/johnlindquist/script-kit-next/blob/v0.1.29/docs/guides/permissions.md) explains what each grant does. The [consent walkthrough](https://github.com/johnlindquist/script-kit-next/blob/v0.1.29/docs/guides/installed-release-consent.md) describes how to test microphone input, selected text and original-field delivery on a spare account.

To check the installed resources without opening a window, run:

```sh
"/Applications/Script Kit.app/Contents/MacOS/script-kit-gpui" --check-installation
```

This check creates a temporary workspace, indexes starter scripts and tests installed settings when Bun is available. It does not record audio, write to your workspace or certify native permissions.
