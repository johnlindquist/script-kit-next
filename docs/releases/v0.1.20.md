# Script Kit 0.1.20 — safer targets and first launch

When tabs move or windows change, Kit now checks the selected browser, window and page again before acting. It refuses a stale or ambiguous target instead of switching to an unrelated tab or moving another document. Safari does not expose a stable tab ID; the observed page must be unique in its original window.

- **Settings:** the settings tools ship with the app. Changes use the active workspace, reject unsupported values, and protect newer edits with revision checks. Reading or validating settings doesn't execute your config. Executable paths and sensitive switches remain manual changes.
- **Bun:** Finder launches and script execution use the same discovery rules, including explicitly configured installations and version managers. See [getting started](https://github.com/johnlindquist/script-kit-next/blob/v0.1.20/docs/guides/getting-started.md).
- **Upgrades:** an alternate Kit workspace leaves the default workspace alone. A mixed legacy kit with unrecognized files is preserved for manual import instead of partially moved and deleted. An unknown microphone permission is no longer reported as ready.
- **Private GitHub backup:** Sync to GitHub exports eligible scripts, scriptlets, agent/skill definitions, personalizations and themes to the dedicated `script-kit-personal` branch of a verified private GitHub repository. It honors ignore rules; it never pushes the local git index or history, config, notes, recordings, tokens or credential vault. A script can contain your own private information; review what you author. Existing remote history isn't erased. If an older backup included credentials, remove that history separately and rotate the affected credentials.
- **Saved credentials:** new vaults use a random private identity in the macOS Keychain. A readable older vault is upgraded atomically on access. A locked or missing key isn't an empty vault. Keep a secure Keychain backup; the encrypted file alone is not a portable credential backup.

**Install:** download `Script-Kit-macos.zip` from the [GitHub release](https://github.com/johnlindquist/script-kit-next/releases/tag/v0.1.20), unzip and open Script Kit on an Apple Silicon Mac. Bun is needed for scripts; microphone and Accessibility permissions are needed only for the corresponding features. Dictation models are downloaded on demand. See [permissions](https://github.com/johnlindquist/script-kit-next/blob/v0.1.20/docs/guides/permissions.md) and [dictation](https://github.com/johnlindquist/script-kit-next/blob/v0.1.20/docs/guides/dictation.md).

**Check your download:** compare its SHA-256 with `zipSha256` in the accompanying installed-workspace check. The signed app's `Contents/MacOS/script-kit-gpui --check-installation` command creates a disposable home, indexes real starter scripts, exercises installed settings when Bun is available, and checks that a second setup preserves personal edits. It does not open a window, record audio, or touch your workspace. The release manifest and scorecard distinguish packaged checks from fixtures; they do not certify every browser, input device, or a particular user's permission grants.
