# macOS release pipeline

A version tag must match the package, lockfile and bundle versions. An unsigned Actions artifact is not an installable GitHub Release. Publication requires the tagged source's test gates, Developer ID signing, Apple notarization, stapling, Gatekeeper and verification of the re-extracted ZIP.

## Compile once; verify at each boundary

`build-macos-app` has no Apple signing credentials. It uses `build-ops act app-build --profile release --features owned-ui-evaluation` to produce an immutable executable. The pinned `cargo-bundle` packages a copy of that executable with `CARGO_BUNDLE_SKIP_BUILD=1`. It does not compile a replacement. `scripts/agentic/release-compile.ts seal` verifies the finalized managed build, the binary in the unsigned bundle and the ZIP. The builder uploads the ZIP and a portable compile receipt, and reports its artifact ID and receipt SHA-256 separately through job outputs.

The signing job downloads that exact artifact from the same run. `verify-zip` checks the independently supplied receipt digest, repository, tag, commit, run, target, compiler and configuration. A later attempt can reuse a successful earlier build of that *same run*. The job validates archive membership before extracting it. `verify-executable` checks the extracted executable before the Apple keychain step. After signing, `verify-signed-payload` checks that only signing-owned Mach-O data changed before the app is sent to Apple.

The portable receipt is historical evidence, not a locally executable reference. No compiler pool, owner token, lease or mutable task registry is copied into the signer. `build-ops act publish-signed-bundle --release-input <receipt> --expected-input-sha256 <producer-output> --bundle <app> --attestation <attestation> --artifact-out <new-reference>` publishes a locally owned, immutable signed derivation with the original compile evidence. It still verifies the app, sidecar, security attestation, normalized program bytes and bundle tree. `--input <local-reference>` remains available for all-local derivations. Supplying both input modes is refused. Never compute the expected digest from the download you are about to verify.

The same unprivileged runner builds the real `export_design_tokens` tool with `exporter-build --profile release --features owned-ui-evaluation`. This reuses the application's compiled Rust library; the exporter is still a separate verified binary and must reproduce the checked-in JSON and CSS byte for byte. The signing job downloads that proof by its exact artifact ID. Standalone exporter builds keep their test profile by default.

## Recovering a stopped compiler proof

The authored-opacity unit and compile-fail checks use `sk-color`, the dependency-free production crate that supplies the launcher's public `theme::alpha` types. Proving six byte operations and three Rust type errors no longer builds the whole application. The full application build and behavior suites remain separate mandatory gates. Only the narrowly recognized cold compiler directory churn may instead produce a **failed measurement**, with its closed-owner receipt, and a one-use digest-bound cache handoff. A fresh Mac can start the *entire* proof immediately without waiting for packaging. A cache hit or refusal alone cannot satisfy the aggregate gate: the signer uses the artifact ID selected by the successful proof, not just its display name. Debug and release builds watch their active compiler directory under the same time, allocation and identity limits. An incomplete sample is never a passing measurement. A test failure, storage-limit breach, unknown identity or diagnostic, missing evidence or cache, unclosed worker, or second refusal stops the release.

A refused `build-ops act` reports a path-free `buildOps.result.resources.refusalClass`. To inspect a retained build without retrying it, use `bun scripts/devtools/devtools.ts build-ops query job --id <task-id> --generation <task-generation>` in its workspace. Read `buildOps.result.task.result.resources.refusalClass` alongside the recorded status and phase. A successful query does not mean the build passed. Known classes name the observation, not necessarily its cause; `unclassified` means there is not enough safe detail to name it. Raw diagnostics stay redacted. No class authorizes a retry.

Only the unprivileged release app compilation sets `SCRIPT_KIT_AGENT_OWNED_COMPILER_SAMPLE=1` on `build-ops act app-build --profile release`. The supervisor stops only its own compiler group before each full disk walk, checks that the group is stopped, and acknowledges its resume. The free-space monitor continues independently. The pause, walk and resume share the original deadline (at most eight seconds); loss of the owner or a missed deadline terminates the owned build. Other writers are not paused and can still invalidate a sample. The exporter, packaging, signer and other jobs do not enable this mode. The build receipt exposes `resources.monitoring.compilerPauses` with confirmed holds, resumes, scans after exit, the longest round trip and free-space responses between hold and resume acknowledgements. None of these authorize retrying a refusal.

If an SDK suite reports failures, `sdk-summary` prints up to eight locations such as `test-mcp-client.ts#2`: the reviewed filename and its one-based terminal case (pass, fail, or skip; running events are not numbered). Unreviewed filenames, case text and error contents are not echoed. A location is diagnostic, never a passing receipt.

For the actual run, inspect the proof and retry jobs separately from signing and publication. A retry doesn't authorize moving the tag, running a different binary or treating a failed measurement as a pass.
