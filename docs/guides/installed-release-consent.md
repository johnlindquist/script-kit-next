# Checking macOS consent on an installed release

**You do not need to grant everything to try Kit.** Dismiss Kit’s own **Set Up Permissions** list with Esc. Try the launcher, a local script prompt, a note, a form and a local setting first. The installed smoke receipt records what actually worked with its starting grants, not what must work on every Mac. A pre-existing grant is not proof that the feature works without it.

Use only a spare Mac or disposable account with no private data, the verified public download in `/Applications/Script Kit.app`, and a blank TextEdit document. Never replace a daily installation. Use synthetic text and, for voice, a few harmless words. Turn off dictation history/recording retention for this test. Don’t reset privacy databases, disable macOS protections, grant Full Disk Access, or give Terminal/your automation runner a grant meant for Kit.

The `settingsStatementBoundary` result tests the settings helper written by the downloaded app. After the app exits, the verifier matches the three helper modules to the tagged source. It runs them with the QA runner’s Bun on separate temporary settings files. A save or reset must refuse `as` or `satisfies` starting on a new line; the type name may start on the next line if the operator stays beside the closing brace. The helper cannot write the installation’s original note or config during this check. This is distinct from the earlier edit performed through the running app’s SDK.

The `commandLink` result checks the command that the installed app wrote to its workspace. After the app exits, the verifier compares `bin/scriptkit` with the tagged source and checks the runner’s Bun against the release’s `.bun-version`. It installs a link in a new temporary directory, runs `scriptkit --help` through a private shell PATH, and checks that repeating the install leaves the link in place. A misleading link to a different, inert executable must be refused without replacing it. The verifier does not run that executable, install anything in your normal command directory, or change the note or setting kept for the upgrade check.

The `settingsSdkScope` result checks the installed SDK, not just its CLI. After Kit quits, the note and config must still match the bytes the running app read back. The verifier imports `sdk/kit-sdk-config.ts` with the release-pinned Bun after matching the module and its three helpers to the public tag. On separate temporary settings, another writer changes the editor font size. An absent revision must not overwrite that change, and an absent key must not reset both font sizes. A one-key reset leaves the terminal setting alone. A whole reset requires the current revision in this check. None of these resets target the installation you will upgrade.

The `paneView` result uses one read-only share on the disposable runner. The released metadata mod runs in a separate, filesystem-confined fixture with synthetic spaces and terminals; no Herdr desktop or core is opened. The installed CLI pairs only the newly offered space. An existing pairing is a refusal. The installed app highlights an observed row without submitting it, follows its identity through reordering, clears selection when a terminal address is reused, and distinguishes an empty space from a withdrawn offer. The verifier revokes the exact offer, removes its own pairing and undoes its named list. The original note and setting must still match. This does not test terminal contents, real Herdr desktop access, focus or zoom.

**What to record:** release tag and archive hash, installed bundle/team identifiers, macOS version, fresh vs upgrade, and one row per attempt: **feature/target | Kit status before | OS prompt actually seen (yes/no/not observed) | user choice | Kit status after/relaunch | observed effect**. No device names, screenshots, audio, document text, or transcripts. `requestedAtUnixMs`, usage descriptions, feature readiness and Kit’s own messages are not OS prompt evidence. `denied` from a boolean AX/screen preflight means “not trusted now”, not necessarily “the user clicked Deny”. Mic `notAsked`, `denied` and `unknown` are different. A zero count **before mic permission** means “not enumerated”, not “no hardware”.

| Receipt step still needing a person | Procedure and passing evidence |
|---|---|
| `mic-first-use-deny` | Start from an account where mic access is `notAsked`. Open **Dictation Setup**; explicitly choose **Request microphone access**. If macOS asks, verify the requesting app and choose **Don’t Allow**. Record that choice separately from Kit’s status. Dictation should not record; a local note should still work. No dialog? Record that, not a denial. |
| `mic-allow-relaunch-and-sound` | In System Settings → Privacy & Security → Microphone allow **only Script Kit**. Quit and reopen the installed copy; recheck status. With an actual input and a verified local speech model, choose **Test microphone** and speak. Record whether sound was detected. “Granted” without sound is not a pass. If no input is available, mark **unavailable — no device**. |
| `ax-selected-text` | Select a synthetic word in TextEdit. First observe Kit’s **Selection** before granting Accessibility (report any unavailable/blocked behavior, not hypothetical fallback). If you want this feature, allow only Kit under Accessibility, relaunch if necessary, reselect the word and verify Kit identifies the intended selection. Record match/no match only. |
| `dictation-original-field-once` | With verified mic and the permissions needed for the selected target, place the cursor between two markers in TextEdit. Use the physical dictation shortcut, say a short phrase, finish, and check the original field once: one insertion between the markers, no duplicate or other field changed. Review/clipboard fallback is **not** successful original-field delivery. |
| `optional-original-window-ocr` | Use a disposable TextEdit document containing an image with an invented term not present as accessible text. **Dictation Setup → Use visible text and window OCR for screen spelling** is optional and may not be in the build. Try without Screen Recording; record the result. Only if testing OCR, grant Kit Screen Recording, relaunch, and repeat the same original-window spelling test (no personal windows). A grant or a correct guess alone does not demonstrate OCR; if no source-specific effect can be distinguished, mark **unverified**. Turn the option off afterward. |
| `target-specific-apple-events` | Only if a chosen local Kit script needs Automation: run a harmless script that asks **TextEdit** for its open-document count, using its AppleScript dictionary, not System Events/UI scripting. Deny an actual prompt and verify the query cannot return the count. Then enable only the actual sender → TextEdit in Privacy & Security → Automation, relaunch and verify the expected count changes when you add a blank document. Record the **actual requesting sender and target**, not a global Automation grant. A different sender is not evidence for Kit. |
| `upgrade-preservation-and-repeat` | On the same disposable account, retain the first release’s synthetic note, script, non-default setting and recorded consent state. Quit, install the separately verified next release at the same path, reopen and confirm the new version/identity. Read the original data **before** writing anything. Repeat the exact tested permission-dependent effect; report prompts, lost grants, unavailable hardware and failures rather than presuming continuity. |

The hosted stdin pass does not answer OS dialogs or operate global input. Report each unperformed step as **requires-human-evidence** (or **not applicable** with a reason). One observed effect must not be used to sign off another permission or release. See [Permissions](permissions.md) and [Dictation](dictation.md) for feature details.
